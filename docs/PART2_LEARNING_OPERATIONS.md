# الجزء الثاني — Learning Operations Baseline

## الهدف
تحويل المنصة من تجربة تدريبية إلى دورة تشغيل صفية مستمرة:
تشخيص → إتقان → مجموعات مرنة → توصية درس → اعتماد المعلم → تنفيذ → دليل تعلم → تحديث الإتقان → توصية تالية.

## ما هو موجود بالفعل
قاعدة البيانات الأساسية تحتوي على:
- organizations / profiles
- classes / students
- skills مع المتطلبات السابقة
- mastery بحالات Gap → Emerging → Developing → Secure → Mastered
- lesson_blueprints
- lesson_evidence
- RLS لعزل بيانات الجهات

كما توجد واجهات النمو المهني وملف الممارسة والكوتشينق ومختبر أدوات التمايز.

## نطاق الجزء الثاني
1. Class Readiness — جاهزية الفصل.
2. Skill Map — خريطة المهارات والفجوات والمتطلبات السابقة.
3. Flexible Groups — مجموعات مرنة تتغير حسب الدليل.
4. Today Journey — رحلة اليوم للمعلم.
5. L1/L2/L3 Paths — مسارات تعلم متمايزة قابلة للتعديل.
6. Exit Ticket — تقويم ختامي سريع.
7. Mastery Update — تحديث الإتقان مع الثقة وعدد الشواهد.
8. Next Recommendation — توصية الحصة التالية.
9. Impact View — أثر التغيير على تعلم الطلاب.
10. Acceptance — اختبارات وظيفية وأمنية وبصرية قبل الإنتاج.

## قواعد المنتج
- أقل مدخلات ممكنة من المعلم.
- لا تثبيت دائم للطالب في مستوى أو مجموعة.
- كل توصية يجب أن تستند إلى دليل تعلم قابل للتتبع.
- المعلم يعتمد أو يعدل التوصية؛ النظام لا يستبدل القرار المهني.
- لا تُرسل أسماء الطلاب إلى طبقة الذكاء الاصطناعي عندما تكفي المعرفات الداخلية.
- لا تكرار للجداول الموجودة؛ التوسع يتم فوق النموذج الحالي.

## Definition of Done
لا يعد الجزء الثاني مكتملًا حتى تنجح دورة حقيقية:
فصل → طلاب → مهارات → تشخيص → mastery → مجموعات → درس متمايز → اعتماد → exit ticket → mastery جديد → توصية تالية،
مع RLS واختبار الجوال وRTL وتقارير الأثر وProduction Acceptance.
